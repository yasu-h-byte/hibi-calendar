# 経営コックピットとの連携

2026-09-25 開始。DEDURA＋（出面・原価）と経営コックピット（keiei_dashboard: 会計・資金繰り・銀行）を一体で使うための約束ごと。

## 考え方
- **出面・現場・取引先・請求額の入力は DEDURA＋**、**お金の流れ（口座残高・13週資金繰り・帳簿との照合）は経営コックピット**
- 経営コックピットは DEDURA＋ の数字を「読むだけ」。DEDURA＋ のデータを書き換えることは原則ない（例外は下の「書き込み（1つだけ）」＝現場別の外注単価の上書き）
- 合言葉は環境変数 `DEDURA_INTEGRATION_KEY`（両方の Vercel プロジェクトに同じ値。16文字以上）。人のパスワードとは別。チャットに貼らない

## 窓口
`GET /api/integration/monthly?ym=YYYYMM`（ヘッダ `x-integration-key`）。実装は `lib/integration.ts`、テストは `__tests__/integration.test.ts`。

返すもの（金額は特記が無い限り**税抜の円**）:
| 項目 | 中身 |
|------|------|
| `sites[]` | 現場ごとの請求額（`billing`・入力済みの額だけ。`billingEntered`）、請求先（`billToName`: 直=一次、応援=担当の同業者）、自社人件費（実支給ベース・出向控除後）、外注費 |
| `subcons[]` | 外注・同業者ごとの支払見込み（出面 × 単価）、マスタの単価・残業単価、現場別の内訳（その現場・月で実際に使った単価つき）。請求書の単価の照合に使う |
| `peerBilling[]` | 応援現場で同業者へ請求する**見込み**（同業者との請求・支払一覧と同じ計算。まだ請求書を発行していない金額も含む） |
| `peerInvoices[]` | 実際に発行・取り消しした「応援の請求書」（`no`・`companyId`・`issueDate`・`dueDate`・`subtotal`（税抜）・`tax`・`total`（税込）・`status`（`issued`\|`void`）・`sites[]`（現場ごとの内訳））。発行済みがあればこちらを確定額として使う（docs/peer-invoice.md） |
| `hfuInvoices[]` | HFU → 日比建設 の請求書（2026-09-26・グループ内。形は `peerInvoices[]` と同じ）。`peerInvoices[]` には含まれない。日比建設から見ると支払い、HFU から見ると入金（docs/peer-invoice.md「HFU → 日比建設 の請求書」） |
| `hfuWorkforce` | HFU 所属の作業員の人数と稼働（2026-09-27）: 在籍人数 `heads`・その月に人工がある人数 `workingHeads`・人工 `workDays`・残業 `otHours`・社内単価での額 `amount`（税抜）・単価 `tobiRate`/`dokoRate`・出面が入っている最後の日 `lastDate`。人件費 `laborCost`（給与計算の支給額・残業や手当を含む・会社負担の社会保険は含まない）とその人工 `laborManDays`、日額の平均 `dailyRateAvg`。人工の数え方は HFU → 日比建設 の請求書の下書きと同じ。締まっていない月は途中の数字。経営コックピットの HFU 黒字化シミュレーター（鳶の売上の見込み）で使う |
| `closed` | 出面が締まった月か（前月より前）。締まっていない月は数字が動く |

- 請求額は「未入力なら 0」。原価・収益管理画面の**見込み請求（人工 × 平均単価）は返さない**（資金繰りに確定額と見込みが混ざらないように）
- Firestore の読み取りは1回の呼び出しで main（30秒キャッシュ）+ その月の att 1件 + `peerInvoices` コレクションへの月次クエリ1件。締まった月は `getAttDataCached`。経営コックピット側も30分キャッシュする

### 受け取った外注の請求書（2026-10-05）
`GET /api/integration/subcon-invoices?from=YYYYMM`（ヘッダ `x-integration-key`）。from の月以降の `subconInvoices`（外注の請求書・支払内訳書）と、`paperInvoices` のうち一次へ出した請求書（現場を選んだもの）を `kind`（received / remittance / issued）付きで返す（2026-10-05 入口の1本化）。
各件に1つ目のファイル（請求書の本体）を取り出す署名つきURL（15分）`file.url` を付ける。添付（2つ目以降）は数（`attachments`）だけ。
金額は請求書に書いてあるとおり（`total` 税込・`subtotal` 税抜・任意）。経営コックピットは毎朝これを読み、まだ取り込んでいない件のファイルを
自分の置き場（Supabase Storage）に写して AI で読む（経営コックピット docs/specs/27-dedura.md）。

### 在籍スタッフの台帳と給料の見込み（2026-10-07）
`GET /api/integration/workers?months=72`（ヘッダ `x-integration-key`）。実装は `lib/integration-workers.ts`、テストは `__tests__/integrationWorkers.test.ts`。
経営コックピットの「人員配置計画」（日比建設の中期計画の人件費と自社の人工）が読む。代表「在籍スタッフは DEDURA＋ から常に引っ張る。人件費は等級ごと、在籍年数で給与が上がる」。
**個人の給与を含む**ので、経営コックピット側も経営者だけが見る。

返すもの（今月から months か月・既定72＝6年。金額は円）:
| 項目 | 中身 |
|------|------|
| `workers[]` | 1人ずつ: 所属（`hbk`/`hfu`）・国籍（`jp`＝在留資格なし / `vn`）・職種（`job`）・在留資格と期限・入社日・退職日・年齢・出向先・現場に出る人か（`field`）・今の給料（`pay`: 日額と等級・号 / 時給 / 月給）・締めた直近の月の実際の支給額（`lastClosed`・残業や手当込み）・月ごとの見込み（`months[]`: 在籍か・まるごと帰国か・基本給・等級と号・時給）・期（10月〜9月）ごとの合計（`years[]`: 基本給・会社負担の社会保険・合計・在籍した月数） |
| `starting` | これから採る人の目安: 等級ごとの1号の日額、ベトナム人の初任の時給（最賃を10円に切り上げ） |
| `assumptions` | 見込みの前提（下）と社会保険の率 |

見込みの前提（給料の決まりはこの DEDURA＋ の1か所。経営コックピットに同じ決まりを書かない）:
- 日本人（号俸）: 毎年10月1日に、評語 A（+4号）＋ 年齢調整で号が上がる（60号まで・下がらない・入社6か月未満は上げない）。昇格は見込まない。月の基本給 = 日額 × 310日（所定290 + 有給20）÷ 12
- 日本人の新卒（月給）: 入社1年は月給のまま、その後は 1G の同じくらいの号へ
- ベトナム人（時給）: 入社した月に毎年、逓減カーブ（A 評価 = カーブどおり）で上がる。月の基本給 = 時給 × 140時間
- 月給の人: 据え置き ／ 役員: 返さない（役員報酬は帳簿で持つ）／ 承認済みの一時帰国でまるごといない月: 0
- 残業・手当・賞与は入れない（経営コックピットが `lastClosed` と比べて補う）
- Firestore の読み取りは main（30秒キャッシュ）+ 帰国の一覧 + 締めの記録（直近4か月 × 3件まで）。経営コックピット側は1日1回ほど

## 書き込み（1つだけ・2026-09-25 午後）
`POST /api/integration/subcon-rate`（ヘッダ `x-integration-key`、本文 `{ subconId, siteId, rate, reason? }`）。
経営コックピットの「請求書の取り込み」で、請求書の単価が DEDURA＋ と違うと1円まで説明できたとき、社長がボタンで押した単価を
現場マスタの現場別単価（`assign[siteId].subconRates[subconId].rate`）に書く。残業単価は書かない（自動計算）。
5,000〜100,000円の整数だけ。記録は activity に `integration` として残る。これ以外の書き込みは無い。

- **書き方（2026-10-02 総合点検）**: トランザクションの中で、この現場・この外注のキーだけをドット記法で書き、**手で入れた残業単価（`otRate`）の上書きは残す**。
  旧は `assign` マップを丸ごと読んで丸ごと書き戻していた（職長の工種の切り替えなど同時の書き込みが消える）うえに `{ rate }` で置き換えていたので、
  現場別の残業単価の上書きが黙って消えた。id は英数字・`_`・`-` だけ（`.` や `/` が入ると別のフィールドを書く）
- `lib/integration.ts` 冒頭の「書き込みは一切できない」というコメントは 2026-09-25 午後にこの窓口を足す前のもので古かった（2026-10-03 に直した）

## 確かめたこと（2026-09-25）
- 8月の請求額 35,565,939円（税抜）× 1.1 = 39,122,533円 は、MF の売掛金「山岡建設工業」8月計上 39,122,562円と29円差で一致。7月（38,006,773円）も一致
- 外注費（出面 × 単価）は MF の買掛金の計上と月によってずれる（残業・交通費・請求の締めの違い・記帳漏れ）。照合は経営コックピットの「現場と外注」で行う

## 経営コックピットでの使い道
- 13週資金繰り: 入力済みの請求額 × 1.1 を「翌々月10日」の入金（山岡建設工業）として使う
- 現場と外注（/genba）: 現場別の売上・原価・粗利、外注ごとの「出面の見込み」と「帳簿の計上」の照合
- `peerInvoices[]`: 同業者へ発行した応援の請求書。`status: 'issued'` の `total`（税込）・`dueDate` を、13週資金繰りの同業者からの入金予定にそのまま使える（見込みの `peerBilling[]` より確度が高い）
- `hfuInvoices[]`: HFU → 日比建設 の請求書。グループ内の請求なので同業者からの入金予定には**含めない**。日比建設の支払予定・HFU の入金予定として使う
- 在籍スタッフの台帳と給料の見込み: 人員配置計画（等級・国籍ごとの人数と人件費・自社でこなせる人工）→ 中期計画（2026-10-07〜）
- 受け取った外注の請求書: DEDURA＋ の「受け取った請求書」に入れたものを `/api/integration/subcon-invoices` で読み、AI で読んで出面・単価・帳簿と突き合わせる（2026-10-05〜）
