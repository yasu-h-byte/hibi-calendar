# 書類庫（スタッフの在留カード・雇用契約書など）

2026-09-28 第1段階。画面 `/staff-docs`（サイドバー「人・賃金 → 書類庫」、人員マスタの各行の「🗂 書類」からも開ける）。

## 目的
在留カード・雇用契約書などを1か所に入れておき、**人員マスタを書類と食い違わない正確な状態に保つ**。
（2026-09 に契約書9通を手で読んで時給・適用日を入れた作業、在留期限を越える契約期間・「13月」の誤記の発見を、将来はシステムがやる）

## 見られる人（lib/permissions.ts）
| できること | 役割 |
|---|---|
| 見る（`staffDocs.view`） | 代表・事業責任者（政仁さん）・事務（森田さん） |
| 入れる・旧版にする・情報を直す（`staffDocs.edit`） | 同上 |
| 削除（`staffDocs.delete`） | 代表だけ |

在留カードは機微な個人情報なので、職長・役員・スタッフ本人には見せない（代表決定 2026-09-28）。

## 仕組み
- ファイル本体: Firebase Storage `dedura-kanri.firebasestorage.app`（東京 asia-northeast1）
  - セキュリティルール = 本番モード（allow read, write: if false）。ブラウザの Firebase SDK からは触れない
  - 公開アクセス防止 = enforced（誤って公開URLにできない）
  - CORS = `https://hibi-calendar.vercel.app`・`http://localhost:3000` からの PUT/GET/HEAD のみ
  - パス: `staff-docs/{workerId}/{docId}/{連番}-{ファイル名}`
- 出し入れはサーバー（Admin SDK・`lib/storage-admin.ts`）が発行する **15分で切れる署名つきURL** だけ。
  アップロードはブラウザから Storage へ直接 PUT（Vercel の API は本文 4.5MB までなので、API 経由にしない）
- 書類の情報: Firestore `staffDocs/{docId}`（`lib/staff-docs.ts` の `StaffDoc`）

### 登録の流れ（app/api/staff-docs/route.ts）
1. `prepare` — 種類・形式（PDF/JPEG/PNG/HEIC）・大きさ（25MB・1件10ファイルまで）を確かめ、署名つきURLを返す（記録はまだ作らない）
2. ブラウザが各ファイルを PUT
3. `commit` — Storage に本当にあるか確かめてから記録を作る。「最新にする」なら同じ人・同じ種類の最新を **旧版** にする（消さない）

## 画面でわかること
- 期限切れ・90日以内（在留期限の更新申請は満了3か月前から出せるため）。在留カードがまだ無い人は人員マスタの在留期限で知らせる
- 人員マスタとの食い違い（第1段階は在留期限だけ：最新の在留カードの期限 ≠ 人員マスタの visaExpiry）
- まだ入っていない必須書類（在留カード・雇用契約書）。パスポートは扱わない（代表決定 2026-09-28）

## 費用
Storage の保存・転送。書類の量なら月に数円程度。予算アラート（月 ¥2,000・50/90/100%）の範囲。
