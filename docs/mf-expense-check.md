# MF経費の申請を自動でチェックする（設計書）

2026-11-08 作成・同日 頻度を1日1回に、月の流れを追記（秘書室の Claude と日比さんで検討）。同日 **第1段階（日比建設・見るだけ）と OAuth 接続を実装**。道具代の自動登録・メール・差し戻しは未実装。

実装の場所: 画面 `/expense-check`（メニュー「締め・請求（毎月）」）／API `app/api/mf-expense/`／決まり `lib/mf-expense-rules.ts`／MF との通信 `lib/mf-expense-client.server.ts`／実行 `lib/mf-expense-run.server.ts`。保存先は [firestore.md](firestore.md)。

## 目的
- 総務（今は森田さん）が MF クラウド経費の申請を承認する前の「目での確認」を減らす。
- 見るのは**引っかかった申請だけ**にする。承認ボタンは人が押す（お金の最後の判断は人）。
- 担当が替わっても回るように、**人ではなく役割（総務）**で作る。森田さん個人のアカウントに依存しない。

## なぜ DEDURA＋ に作るか
チェックに使うデータの大半が DEDURA＋ にある。
- 出勤日 = 出面（att）
- 道具代 = 道具代管理（`demmen/toolBudget`、`app/api/tool-budget`、manual-morita.md §4）
- 総務が毎日使う画面も DEDURA＋
経営コックピットは「お金の流れ」を見る側なので、今回は DEDURA＋ 側に足す（経営コックピットへは必要なら後で読ませる）。

## 分かっていること（2026-11-08 に MF の画面と API 文書で確認）
- **API は今の契約で使える**（日比建設のプランは「コーポレート」）。個人設定 → 基本設定 →「API連携（開発者向け）」でアプリを登録する。まだ1つも登録されていない。
- 認証は OAuth 2.0（認可コード）。承認した人の権限でトークンが出る。リフレッシュトークンあり。
- 使う API（`/api/external/v1/offices/{office_id}/...`）
  - `GET /offices`：事業者の一覧（日比建設 9184-0128・HFU 8033-7801）
  - `GET /approving_ex_reports`：事業者全体の**承認待ち**の一覧
  - `GET /ex_reports/{id}/ex_transactions`：申請に含まれる経費明細
  - `GET /ex_transactions/{id}/mf_file`：添付（領収書）
  - `GET /ex_transactions/{id}/ex_journal`：明細の仕訳（科目）
  - `GET /suspense_payment_reports`：仮払申請の一覧
  - `POST /me/approving_ex_reports/{id}/disapprove`：差し戻し（第4段階まで使わない）
- 定期区間は**全員未設定**。交通費は「出勤日と合うか」「いつもの金額と比べて」で見る。
- 従業員：日比建設 約35人（大半が現場）、HFU 約40人（建設・飲食・不動産・本部）。
- **HFU の店舗スタッフ（飲食など）は MF経費を使っていない**。交通費は出勤に合わせて給与で払っている（2026-11-08 日比さん）。→ 対象外。
- HFU で MF経費を使うのは主に建設（ベトナム人スタッフ）・本部・不動産。HFU の建設スタッフの出勤は DEDURA＋ の出面にある（integration.md の `hfuWorkforce` と同じ）。

## 交通費の決まり（2026-11-08 日比さん）
- **実費**。今のところ**上限なし**。定期区間は使っていない。
- **車通勤はガソリン代の領収書を出して精算**する。ガソリンは給油した日と出勤した日が一致しないので、日付ではなく**月の合計**で見る。

## 対象
- 第1段階：日比建設（全員）
- 第2段階：HFU の建設スタッフ（出面と照らせる）。本部・不動産は出面が無いので、T1〜T3 を外し、日付・二重・領収書・科目（D1・D2・R1・K1）だけ見る

## 月の流れ（運用の決まり・2026-11-08 日比さん）
- **前月分の経費を、当月10日ごろまでにまとめて申請する**のが決まり。
- ただし月末に当月分を出す人もいる（2026-10-31 に 10月分の例）。**16日以降に出て当月の明細のほうが多い申請は当月分として見る**。15日までは前月分として見て、当月の日付が混ざれば D1 で知らせる。
- キャシュモへの格納の締め切りは当月15日（「04_経費精算_15日まで」）。承認はその前に終える。

| 日 | 起きること | この仕組みがすること |
|---|---|---|
| 1日〜10日 | 前月分の申請が集まる | 毎朝、新しく出た申請をチェックし、引っかかったものを一覧に出す |
| 8日 | 締め切りが近い | 前月に出勤があるのに、まだ申請していない人の一覧を出す（M1） |
| 11日 | 締め切りの翌日 | まだ出していない人・差し戻したままの人の一覧を出す（M2） |
| 11日〜14日 | 総務が承認 | 「✓ チェック済み」の申請はそのまま承認、引っかかったものだけ見る |
| 15日 | キャシュモへ格納 | （書類の受付箱の仕組みと同じ流れ） |

## 動き方
1. **1日1回、朝7:00**（Vercel cron。MF は毎日 1:00〜6:00 がメンテナンスなのでその後）に、日比建設の `approving_ex_reports` を読む。
2. まだ見ていない申請（申請ID＋更新日時で判定）だけ、明細・仕訳・添付の有無を読む。
3. 下の「チェック」を当てて、結果を Firestore に保存（申請ごとに 1件。`expenseChecks/{reportId}`）。
4. 総務の画面「経費の事前チェック」に一覧を出す（引っかかった申請が上、問題なしは「✓ チェック済み」）。
5. 引っかかったものがあれば、総務の共通アドレス **somu@faceo.co.jp**（Google グループ「総務」・2026-11-08 作成。hfu.co.jp でも届く想定）にメールで知らせる（第2段階から）。

## チェック（最初の版）
| ID | 見るもの | 引っかける条件 | 重さ |
|---|---|---|---|
| T1 | 交通費 × 出勤日 | 交通費の日付に、その人の出面が無い（休み・欠勤） | 要確認 |
| T5 | 同じ現場の交通費 | 同じ人・同じ現場（1日1現場の日だけ）で、その月3日以上あるうち、一番多い日の交通費の合計より「見逃す差」（既定300円・画面「決まりの数字」で変更）を超えて違う日がある。曜日やルートで変わる小さな差は出さない。一番多い金額が1つに決まらなければ出さない | 要確認 |
| T6 | 同じ区間の社内の最安 | 内容欄の「A~B 往復／片道」で区間を読み、社内で2回以上出た金額の最安より「見逃す差」（既定0円＝小さな差も拾う）を超えて高い。画面「区間の比較」で区間ごとに人と金額を並べて見られる（`mfExpense/routeTable`）。申請ごと・区間ごとに1回。経路の決まりは最安ルート（2026-11-09 代表）。本当の最安は外部の運賃 API が要るので、社内の実績の最安と比べる | 要確認 |
| T3 | 交通費の金額 | その人の直近3か月の同じ経路・同じ科目の金額と大きく違う（±30%を目安）。上限が無いので、ここが金額の見張り役 | 参考 |
| T4 | ガソリン代 × 出勤日数 | 前月のガソリン代の合計 ÷ 出勤日数が、その人の直近3か月の平均と大きく違う（±30%を目安）。領収書が無いものは R1 で引っかける | 参考 |
| D1 | 日付 | 前月以外の日付（未来の日付、前々月以前の出し忘れ） | 要確認 |
| D2 | 二重 | 同じ人・同じ日・同じ金額・同じ科目の明細がほかの申請にもある | 要確認 |
| R1 | 領収書 | 添付が無い（交通費など領収書の要らない科目は除く） | 要確認 |
| R5 | 交通費と駐輪場代 | 交通費の金額と、添付の領収書の読み取り金額が違う（電車代に駐輪場代を足している）。差し戻して分けてもらう | 要確認 |
| K2 | 駐輪場代の疑い | 交通費の科目で、「駐輪・駐車」の字があるか、添付があり区間が読めず電車の言葉も無い500円以下の明細。申請ごとに1回（ほか n 件） | 要確認 |
| U2 | 科目が未設定 | 種類が未設定の科目の明細がある（チェックしていないことを「チェック済み」に見せない） | 要確認 |
| K1 | 科目 | 摘要と科目が合わない（例：摘要に「電車」「バス」なのに交通費以外の科目） | 要確認 |
| G1 | 道具代 × 台帳 | 道具代の科目なのに、その人が道具代の対象外（役員・事務・入社6か月未満・期間未設定） | 要確認 |
| G2 | 道具代 × 残額 | 承認すると残額がマイナスになる | 要確認 |
| G3 | 道具代の折半 | 摘要・コメントに「折半」「半額」がある、または領収書の金額と申請額が合わない。自動登録しない | 要確認 |
| M1 | 申請の出し忘れ | 8日の時点で、前月に出勤があり交通費などが毎月出ている人の申請がまだ無い | 参考（総務から声かけ） |
| M2 | 締め切り後 | 11日の時点で、まだ申請が無い人・差し戻したまま直っていない申請 | 要確認 |

- 「要確認」= 総務が見る。「参考」= 一覧に出すだけ。
- 決まりの数字（±30% など）はコードに埋めず、設定（Firestore）に置いて画面から変えられるようにする。

## 道具代の自動登録（効果が大きい）
いまは「MF で承認された道具の購入を、総務が DEDURA＋ の道具代管理に1件ずつ手で登録」している（manual-morita.md §4-3）。
- 承認された（`approving` から消え、承認済みになった）道具代の明細を、道具代管理の購入履歴に**自動で登録**する。
- 二重登録を防ぐため、購入に MF の明細ID（`mfTransactionId`）を持たせる。既にあれば登録しない。
- 登録したものは画面に「MF から自動登録」の札を付け、総務が取り消せるようにする。
- **道具代の決まり（2026-11-08 日比さん）**：ふつうは**予算の範囲で全額を会社が負担**する。台帳には MF で承認された額をそのまま入れる。
- **折半（会社と本人で半分ずつ）はかなりまれ**で、決まった工具だけ。摘要やコメントに「折半」「半額」とある明細、または領収書の金額と申請額が合わない明細は**自動で登録せず**、総務の確認に回す（G3）。

## 段階
1. **見るだけ（2週間）**：一覧に出すだけ。総務のいつもの確認と見比べ、誤った指摘が多い決まりを直す。
2. **総務へのメール**：引っかかった申請があるときだけ知らせる。
3. **申請した本人への知らせ**：どこが合わないかを本人に伝え、本人に直してもらう。外国人スタッフにはやさしい日本語（必要ならベトナム語を添える）。
4. （任意）明らかなミス（D1 の未来日付、R1 の領収書なし）は理由を書いて自動で差し戻す。日比さんが決めてから。
- 道具代の自動登録は、1 が終わって合っていると分かってから始める。

## 決まったこと（2026-11-08 代表）
- **経費科目**: 接続後に MF から一覧を取り込み、画面「科目の種類」で 交通費／ガソリン代／道具代／その他（領収書不要・必要）を割り当てる。未設定の科目は、科目で決まるチェックをしない
- **従業員の結びつけ**: MF の従業員番号とキャシュモ番号（人員マスタの `payrollNo`）が1対1で一致した人は自動。それ以外は氏名の近い作業員を候補に出し、総務が画面で確定する。氏名だけでは自動で結ばない。未確定の人の申請は出面・道具代を見ず「作業員が未確定」と出す
- **見られる人**: 事務・事業責任者・代表（`expenseCheck.view` / `expenseCheck.edit`）。MF との接続・切断は代表だけ（`system.admin`）
- **メニュー**: 「締め・請求（毎月）」の「請求・原価」の下

## 接続のしかた（最初に一度・代表）
鍵はチャットや文書に書かない。Vercel の環境変数にだけ入れる。
1. MF経費に**日比さん（管理）のアカウント**でログインし、個人設定 → 基本設定 → 「API連携（開発者向け）」でアプリを作る。Redirect URI は `https://hibi-calendar.vercel.app/api/mf-expense/callback`
2. 表示された Client ID と Client Secret を、Vercel の Settings → Environment Variables に入れる（`MF_EXPENSE_CLIENT_ID` / `MF_EXPENSE_CLIENT_SECRET`、Environment は Production）。Secret は Sensitive にする
3. Redeploy してから、本番の `/expense-check` で「MF経費につなぐ」を押し、MF の画面で承認する（Preview では接続できない。Redirect URI が本番だけのため）
4. 「今すぐチェック」を押して科目と従業員を読み込み、「科目の種類」と「従業員の結びつけ」を埋める

Client Secret を入れ替えたら、保存したトークンが読めなくなるので、つなぎ直す。

## 実装で分かったこと（2026-11-08）
- 事業者全体の申請を読む API は `office_setting:write` が必須で、読み取りだけの権限は MF に無い。求める権限はこれと `user_setting:write`（事業者一覧）だけ。承認・差し戻しの `report:write` は求めないので、第4段階までこの接続では差し戻せない。コードも GET だけ（`__tests__/mfExpense.test.ts` が見張る）
- 明細の API に科目と添付の有無が入っているので、`ex_journal` と `mf_file` は呼ばない
- **G3 の「領収書の金額と申請額が合わない」は第1段階では見ていない**。API に領収書の金額が無いため。「折半」「半額」の言葉だけで引っかける
- 「出勤した日に交通費が無い」（旧 T2）は 2026-11-09 にやめた。皆で車に乗り合わせて通う日があり、つけ忘れと区別できないため。電車代があるのに出面が無い日（欠勤の疑い）だけを T1 で拾う
- M1・M2 の「申請が無い人」は、前月より前の3か月のうち2か月以上申請があった人だけ
- **承認の段階（2026-11-09 代表）**: `approving_ex_reports` は事業者全体の承認待ちで、申請ごとに `status`（`waiting_step_one` など）と `ex_report_approvals`（段階・今の承認者・承認日時）が付いてくる。追加の通信なしで保存し、「○○さんの承認待ち」を一覧に出す。更新はチェックのとき（毎朝7時か「今すぐチェック」）
- **領収書の読み取り（2026-11-09 代表）**: MF の API に領収書の日付・金額は無いので、添付（`ex_transactions/{id}/mf_file`）を Claude（`claude-opus-5-5`）で読む（`lib/mf-expense-receipt.server.ts`）。画像は保存せず、読んだ日付と金額だけ `expenseReceiptReads` に残す。1枚1回だけ（添付が差し替わったら読み直す）。毎朝 7:20・7:40 の cron（`/api/mf-expense/receipts`）で読み、読めたらチェックをやり直す。鍵は Vercel の `ANTHROPIC_API_KEY`（無ければ何もしない）。R2（日付のずれ）・R3（金額のずれ。折半は比べない）は精度を確かめる間は「参考」で出す（`MF_RECEIPT_FLAG_LEVEL`）。R5（交通費の金額のずれ。駐輪場代は電車代と分けて「駐車場・駐輪場代」で申請する決まり）は差し戻す決まりなので「要確認」で出す（2026-11-09 代表・10月分から）。読めなければ R4（参考）。確信が持てない項目は AI が null にして比べない
- **交通費の決まり（2026-11-09 代表）**: 駐輪場代は電車代と分ける（すでに出ている10月分も差し戻す）。少し高くても早いルートを使うのは自由だが、経費精算は一番安いルートの金額まで（差額は自己負担）。
- **総点検（2026-11-09）**: 交通費と出勤日の照合は「現場に出た日」で見る（0.6補は含めない・`wasAtSite`）。科目の照合は駐輪・駐車の明細と、ガソリン代の店名を電車の言葉で見ない。確認メモには確認時の指摘（`review.flagKeys`）を残し、増えたら要確認に戻す。添付があるのに読めていない枚数は `receiptPending` に残し、読むまで「✓ チェック済み」にしない（札は「領収書 未確認」）。1件の申請の明細が読めなくても残りは続ける（X1・要確認）。差し戻し一覧（`expense_reports`）が読めなくても朝のチェックは失敗にしない（声かけに1行出す）。MF の空の応答では科目・従業員の結びつけ・明細の控えを上書きしない。一覧から消えて戻った申請の確認メモは保つ。
- **HFU の技能実習生（2026-11-09 代表）**: HFU に特定技能の人はいない（今後も）ので、対象は技能実習生だけ。11月分から（`MF_HFU_FROM_YM`）。「決まりの数字」の `hfuEnabled` を入れるまで動かない。MF の事業者は「エイチエフユナイテッド株式会社」（`mfHfuOffice`）。トークンは同じ接続を使う（`api.forOffice`）。読む申請は結びついた実習生と、氏名の近い実習生がいる人だけ（本部・不動産の明細は読まない）。候補のいない人は「未確定」に数えない。区間の比較と最安は2社一緒（HFU は結びついた実習生だけ）。毎朝 7:05・7:15 JST に `?org=hfu` で別に動かす。
- **総チェック（2026-11-09）**: 区間の最安の比較は、領収書から駐輪場代の混入が分かる明細は電車代の分で見る（`mfParkingInFare`）。朝のチェックの停止・接続切れ・領収書の問題は通知ベルに出す（`loadMfHealthProblems`・`expenseCheck.edit` の人）。8時を過ぎて今日の完了が無ければ出るので、cron が動かなかった日も分かる。トークンの更新は 400/401/403 のときだけ接続切れにする（5xx や通信エラーは次の回にやり直す）。承認待ち一覧は項目が無い応答を例外にし、全部閉じない。7:20 の再チェックが失敗したら 7:40 にやり直す（`recheck`）。
- **差し戻しコメント（2026-11-09 代表）**: 要確認の指摘から、本人が直せること（T1・D1・D2・R1・R2・R3・R5・T5・T6・K1・K2・G3）を定型文で下書きする（`lib/mf-expense-comment.ts`）。言語の初期値は結びついた作業員の在留資格（日本人＝日本語、それ以外＝ベトナム語）で、画面で切り替えられる。総務がコピーして MF の差し戻しに貼る。MF には書かない。G1・G2 は代表の判断なので文面にしない
