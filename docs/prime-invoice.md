# 一次（山岡建設工業）への請求書

2026-10-20 代表指示。自社現場（笹塚・IHI など、山岡建設工業から直接受けている現場）の毎月の請求書を、
山岡 → 大林組 の請求書（控え）の PDF から自動で作る。画面は `/prime-invoice`（請求・支払 →「山岡への請求書」）。

## 背景（なぜ作ったか）

- 山岡が大林組へ出す請求書（控え）は、契約（工種）ごとに1枚。枚数は現場の契約の本数で決まる（IHI は1枚、笹塚は5枚前後: LC・WPF 足場／TC・仮設EV／コンクリート打設／仕上足場／地上仮設整備鳶・土工手間 …）。
- 日比建設は、その「今回請求金額計」（税抜）の **85%** を山岡に請求する（現場マスタの受取単価と同じ決まり。常用単価 36,000 → 受取 30,600）。
- 借受職人の調整があるときは、山岡から「所属元の異なる借受職人給与の控除」のメモ（控除計算書）が付く。
  - **他社から借りた職人**（吉本の志賀さんなど）の人工分は、85% を掛ける**前**に大林組の請求額から引く（その分は山岡が貸し元へ別に払う）
  - **山岡が直接払っている日比の人の給与**（出向者・大川さん）は、85% を掛けた**後**に引く
- これを事務が手で写して山岡のフォーマットに書いていたので、写し間違いが起きた（2026年9月分の地上仮設は 10,519,207円 が正しいのに 13,123,000円＝100% のまま出した）。

## 計算（1枚 ＝ 大林組の控え1枚 ＝ 工種1つ）

```
base        = 今回請求金額計（税抜） − Σ 他社借受の人工分
ratioAmount = floor(base × 85%)
amount      = ratioAmount − Σ 山岡が払った給与（控除）          ← 請求額（税抜）
tax         = floor(amount × 10%)、total = amount + tax
```

例（架空の数字）: 控え 9,788,000円、他社借受 72,000円、給与控除 440,000円 → (9,788,000 − 72,000) × 85% = 8,258,600 → − 440,000 = **7,818,600円**（税込 8,600,460円）。

- 控除計算書の「日比建設支払額（税別）」と計算が合わないときは注意を出す（山岡の端数の扱いの違いか、読み取りの誤り）
- 調整の無い工種は単純に 85%（1,000円単位の 85% は 50円単位なので端数は出ない。出たら切り捨て）
- **割合は発行ごと（請求書ごと）に変えられる**（2026-10-20 代表: IHI は事情があって 90% の月がある）。下書きの間に「割合を変える」で % と理由を入れると
  全部の枚を計算し直す（`ratio`・`ratioNote`）。85% 以外は一覧・詳細に黄色の印が出て、確認1・確認2の人が見る。控除計算書は 85% で書かれているので、
  割合を変えた月は「メモの支払額と合わない」注意が出る（想定どおり）。現場の受取単価（原価・収益）は変えない（全現場 85% のまま）
- 月の請求書は「一次会社 × 現場 × 対象月」で1つ（`primeInvoices` の1件）。中に工種ごとの枚（`sheets[]`）を持つ

## 使い方（森田さん）

1. 大林組の控え（工種ごとの PDF）と、あれば山岡の控除計算書（PDF）が届く
2. 「山岡への請求書」→「控えを入れて作る」→ 請求先（山岡）・現場（笹塚 など）を選び、PDF をまとめてドロップ →「読み取って下書きを作る」
3. 読み取った枚の表（大林組への請求額 → 切り出し → ×85% → 給与の控除 → 請求額）と、**出面との検算**を確かめる
   - 読み取りの注意（黄色）が出たら中身を見る。読めなかった数字は枚の「直す」で手で入れられる
   - 控除計算書が無い月に切り出し・控除が要るときも「直す」で入れる
4. 「発行を申請」→ 政仁さん（事業責任者）が「確認1」→ 代表が「確認2して発行」→ 番号が付く（HCP-202609-01 のように応援の請求書と別の連番）。
   承認ルートは **格納（森田さん）→ 確認1（政仁さん）→ 確認2（代表）** の3段（代表決定 2026-10-20）。申請した人は確認1を、確認1をした人は確認2をできない。
   **代表だけは「代表が1回で発行」で確認1・確認2をまとめて発行できる**（下書き・確認1待ちのどちらからでも。記録に「代表（1回で発行）」と残る・`issueDirect`）
5. 「印刷 / PDF保存」で山岡のフォーマット（A4 横・工種ごとに1枚）を印刷して送る

控えは翌月15日前後に届くので、画面の既定は前月。通知ベルに承認待ちが出る。

## 出面との検算

山岡が大林組へ出す人工は **前月21日〜当月20日**（出来高調査日は当月末・帳票は翌月15日）。
**主役は「大林組への請求額の全枚の合計」と「出面の総人工 × 常用単価」の差**（`checkPrimeOverall`・3% 以内 ok・10% 以内 warn・それ以上 bad）と 1人工あたりの請求額。
控除計算書の「大林組への請求額」の内訳（鳶工 ○人・残業 ○H …）は**手間契約1本分だけ**なので、出面全体とは比べず参考として出す（`memoManDayRows`・2026-10-20 代表指摘。最初は内訳と出面全体を並べて赤が出ていた）。

- 除外は応援の請求書と同じ（有給・欠勤・現場休・帰国中・試験・休業補償(0.6)・鳶土工以外）
- **出向者は含める**（山岡は出向者の人工も大林組に請求し、給与を控除する）。人ごとの内訳に「出向」の印
- 他社から借りた人（志賀さん）は出面に無いので、その分はメモの方が多くなる（切り出し分と一致するはず）
- 出面側の金額 = 人工 × 常用単価 ＋ 残業h × 残業単価（常用単価 ÷ 8 × 1.25。36,000 → 5,625・28,000 → 4,375）。単価は現場マスタの「単価」タブ（対象月に有効なもの）。
  現場に記載が無ければ管理者設定の単価の規定値（`getSiteRates` の既定）。IHI は記載が無いので規定値で検算する（代表確認 2026-10-20）
- 出来高払いの工種（足場・コンクリートなど、契約額の累積査定）は人工と1対1ではないので、全体の差は目安。笹塚は出来高の工種が多いので数%の差は出る

## 発行の流れと鍵

- 申請・取り下げ・下書きの作成/修正/削除 = `invoice.request`（事務・事業責任者・代表）、確認1・差し戻し・取り消し = `invoice.approve`（事業責任者・代表）、
  **確認2（発行）= `invoice.issuePrime`（代表だけ）**、見る = `invoice.view`
- 下書き（draft）→ 申請（pending・確認1待ち・内容と自社情報を凍結）→ 確認1（checked・確認2待ち）→ 発行（issued・番号）→ 取り消し（void・番号は欠番）。
  差し戻し（確認1・確認2のどちらの段でも）・取り下げ（確認1待ちの間だけ）は下書きに戻す（ファイルと内容は残る・確認1も消える）
- 通知ベル: 確認1待ちは事業責任者・代表に、確認2待ちは代表だけに出る
- 人工の期間の全部の日に職長承認と最終承認がそろっていないと申請・発行できない（応援の請求書と同じ。2か月にまたがるので月ごとに見る）
- 同じ現場・同じ月に「紙の請求書の控え」の一次への請求書が入っていると発行できない（二重請求の防止）
- 同じ会社・現場・月に生きている（void 以外の）請求書は1つ
- 採番と「発行済みが無いか」は応援の請求書と同じ合図（`withInvoiceMonthLock`）で直列にする

### 給与の鍵（CLAUDE.md「給与の取り扱い」）

控除の給与額（大川さんの月の給与）は個人の給与なので:

- API は `pay.view` の無い人には控除の額・85% の額・控除計算書のファイルを伏せて返す（`maskPrimeBundleForViewer`）。請求額そのものは出す
- 控除計算書のファイルを開く・外す・控除の額を直すのは `pay.view` の人だけ
- 操作ログ・経営コックピットには給与の内訳を渡さない（控除の合計だけ）
- 請求額から逆算すれば控除の合計は分かる（85% の元の額と請求額の差）。請求を扱う事務は給与を見られる人（森田さん）なので、画面の見え方で止める以上の守りはしていない

## PDF の読み取り

- 大林組の控え・山岡の控除計算書はどちらも**文字入りの PDF**（Excel・基幹システムからの出力）。`pdfjs-dist` で文字と座標を取り出し、同じ高さを1行にまとめて左から並べる（`lib/pdf-text.server.ts`）
- 控え: ラベル（取引件名・今回請求金額計・消費税額・最終帳票金額・帳票No/帳票年月日・出来高調査日・工事場所受渡し場所名称・発注者名・会社名）の右隣の値を取る。「今回請求金額計(調整前)」とは区別する
- 控除計算書: 「■大林組への請求額」の次から最初の「計」までが内訳、「○○分出面」〜「計 →×85%」が他社借受、「○○支払額（税別）」の行から 計・×85%・▲（控除）・支払額、「○○分差引」から名前
- メモがどの工種の控えのものかは、まず金額（メモの「計」＝控えの今回請求金額計）、次に工種名で合わせる
- スキャン画像の PDF は文字が取れない → その枚は「直す」で手入力
- 大林組の控えは MS 明朝が埋め込まれていないので、pdfjs 同梱の CMap を使う。Vercel では `next.config.js` の `outputFileTracingIncludes` で `cmaps/` と `standard_fonts/` を API に同梱する

## データの置き場所

- `primeInvoices/{docId}`: 1件 = 一次会社 × 現場 × 対象月（`lib/prime-invoice.ts` の `PrimeInvoiceBundle`）。日次バックアップの対象（`primeinv_*`）
- ファイル本体: Firebase Storage `prime-invoices/{docId}/{stamp}-{i}-{name}`（書類庫と同じバケット）。バックアップの対象外
- アップロードは **API 経由**（ブラウザ → `/api/prime-invoice` upload → サーバーが Storage に置く）。置き場の CORS は本番の URL からの
  直接 PUT しか許可していないので、書類庫・紙の控えと同じ「署名つきURLへ直接 PUT」だと Vercel の Preview で止まる（2026-10-20 に Preview で判明）。
  この機能の PDF は小さい（控え 数KB・控除計算書 数百KB）ので API 経由でよい。1ファイル 4MB・1回の送信 3.5MB まで（超えると画面が分けて送る）
- 自社情報（宛名・登録番号・振込先）は発行時に `issuer` に凍結（下書きの間は作成時の内容）

## 経営コックピットとの連携

`/api/integration/subcon-invoices` の `kind: 'issued'` に、発行済みの枚を工種ごとに1件ずつ足す（`prime: { source: 'system', gcAmount, deductions, ratio, bundleNo, siteId }`）。
ファイルは無し（印刷は DEDURA＋ の画面）。給与の内訳は渡さない。

- 画面: `app/(app)/prime-invoice/page.tsx`、印刷面: `components/invoice/PrimeInvoiceDocument.tsx`（山岡の 2023.09版 フォーマットに倣う。
  2026-10-20 に元の PDF を 96dpi の画像（1123×794px）にして寸法を測り、余白（上 23mm・左 12.5mm・右 7mm。右が狭いのは元の書式どおり）・列幅（左 169mm・間 9mm・右 98mm）・
  各枠の高さ（px）・文字の大きさを合わせた。`@page` の余白は 0 で、余白は `.prime-page` の padding が持つ。
  **行の高さの基準（line-height）は `.prime-root` と表のセルで必ず固定する**（画面の親の 24px を継ぐと枠が 6px ずつ伸びて 232mm になり、5枚が10ページに割れた・2026-10-20 代表指摘）。
  Chrome では td の height が行の高さそのもの（padding は足されない）。印刷では `.prime-page` を高さ 210mm・はみ出しは切る（1枚 = 必ず1ページ））
- テスト: `__tests__/primeInvoice.test.ts`（架空の数字。実在の人の給与は書かない）

## 支払内訳書との突き合わせ（入金のチェック・2026-10-20）

山岡から届く支払内訳書は「受け取った請求書」（`/subcon-invoice`）に種類「支払内訳書」で入れる（支払元＝山岡・対象月・振込額）。
同じ会社・同じ対象月について、**発行済みの山岡への請求書の税込合計（全現場）と、支払内訳書の振込額**を比べる（`comparePrimeWithRemittance`）。

- `/prime-invoice` の月の画面に「支払内訳書との突き合わせ」の帯（会社ごと）。`/subcon-invoice` の支払内訳書の行にも同じ見比べの札
- 一致・ほぼ一致（1,000円以内＝端数・振込手数料）・差・支払内訳書がまだ・振込額が未入力・請求書が未発行
- 現場ごとの支払対象額や差し引きの内訳までの照合（帳簿との突き合わせ）は経営コックピットが支払内訳書を AI で読んで行う（docs/integration.md）

## 原価・収益・経営コックピットとの整合（2026-10-20）

- **発行すると、現場の請求額（原価・収益の `billing[siteId_ym]`）を発行した請求書の税抜（工種ごとの額の配列）で上書きする**（`syncSiteBillingFromInvoice`・操作ログ `billing.update` に「山岡への請求書 … の発行で自動」と残す）。
  原価・収益で手で入れた額と請求書が食い違わないようにするため。取り消しのときは触らない（作り直して発行すれば上書きされる）
- 経営コックピットには月の窓口 `/api/integration?ym=` の `primeInvoices[]`（発行済み・取り消し済み・工種ごとの内訳・給与の内訳は無し）で渡す。
  `sites[].billing` も同じ額になるので、13週資金繰り（請求額 × 1.1 を翌々月10日の入金）はそのまま正しい
- 受け取った請求書の窓口（`/api/integration/subcon-invoices`）には**出さない**（経営コックピットの取り込みはファイル必須で、無いと毎朝「失敗」に数えられるため。2026-10-20 に一度出していたのをやめた）
- 「請求・支払の一覧」（`/peer-statement`）に「山岡への請求書（自社現場）」のカードを出す（同業者との貸し借りの合計には入れない）

### 入口の一本化（2026-10-20 代表「機能や画面も統合」）

| 場所 | 変更 |
|---|---|
| 原価・収益の請求額欄 | 請求先が一次の自社現場は **2026年9月分以降、手入力欄を出さない**。下書き・確認待ちの請求書があればその税抜を売上に使い（`invoiceBilling`・「請求書（下書き）」表示・見込みにしない）、無ければ「山岡への請求書で作る」の案内だけ。発行済みの月は読み取り専用（番号とリンク）＋ API（`/api/cost` POST）で 409。8月分以前は従来どおり手入力 |
| 紙の請求書の控え | 一次（山岡建設工業など）への請求書は**新しく入れない**（`prepare`/`commit` を拒否・画面の選択肢からも外す）。2026-10-20 より前に入れた記録は見る・直す・消すだけ。二重請求の防止（紙の控えがある月はシステムから発行しない）は残す |
| 受け取った請求書 | 外注の請求書と共用なので画面はそのまま。支払内訳書の行に山岡への請求書との見比べの札 |
| 応援現場の請求額 | 紙の控え（応援の請求書）を登録・修正・削除すると、その会社の応援現場の請求額に紙の税抜が自動で入る（工種サイトが複数なら出面の見込みの比で割り振り・`allocatePaperToSites`・2026-10-20）。手入力は人工の無い月など例外だけ |
